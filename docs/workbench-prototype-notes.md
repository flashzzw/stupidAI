# W03 核心流程原型与走查

日期：2026-09-30。问题：用户能否在配置、目标、验证、接手与恢复五条流程中辨认当前状态和下一步，并看见关键失败原因？

直接打开 [workbench-prototype.html](workbench-prototype.html) 即可，无安装、构建或服务依赖。原型使用内存模拟数据；五个场景独立，切换/刷新即重置。它不连接 CLI、不产生用量、不保存用户配置，也不属于旧 Web 控制台的生产入口。

| 流程 | 正常路径 | 可操作的失败／边界 |
|---|---|---|
| 配置接入 | 选择 WSL 环境与 Linux 路径，检查并登记配置 | Windows 路径拒绝；Claude 未认证不妨碍 Codex；目录别名标记共享 |
| 交给 Lead | 填目标，查看默认范围/能力，创建一次执行 | 空目标、认证未就绪；重复提交返回同一执行；能力选择与强制规则分开 |
| 打回修复 | Reviewer 失败→Implementer 修复→当前产物验证→交付 | 后续改动使旧证据失效；失败证据与旧版本保留 |
| 人工接手 | 暂停自动派发→核对原执行→交接输入 | 在途工具、未处理草稿、断连、未验证独立前台都不能直接取得输入权 |
| 恢复差异 | 原会话恢复；空闲时改配产生新快照 | 在途改配不生效；供应商切换不能直接 resume；显式新尝试保留原身份和快照 |

每个场景有逐步引导及自由操作按钮。右侧展示可读的当前状态，底层身份在详情中展开；从原型返回的“通过/失败”始终指模拟状态，不能充当原生实验结果。

## 浏览器走查

使用配置的 Playwright 浏览器实际点击，记录于 [W03-browser.json](../goals/evidence/W03-browser.json)。五条引导共 26 步走通；17 项自由操作检查通过，包含空目标、重复提交、旧证据失效、草稿/在途/断连交接、配置快照、供应商切换与键盘导航。1440、768、390 像素宽度的五个场景均无页面横向溢出，最终走查无 JavaScript 异常。

走查中调整：配置输入不再因重绘吞掉首次操作；能力勾选保持详情展开与焦点；切换到未验证接入样本立即撤回旧输入权；显式新尝试显示保留的旧会话；尚未执行时不显示已生成的快照或产物。浏览器脚本曾因没有展开“模拟运行状态”而等待隐藏按钮，修正走查操作后重跑通过；不将此当作产品缺陷。

## 可带入后续实现的结论

- 配置的“连接成功”和“认证可用”要分开；来源、别名及原生强制资源需要可展开。
- 接手先暂停后续调度；工具、草稿、身份未核对完成时持续显示原因，而不是开放发送按钮。
- 验证跟随产物版本，改配跟随快照版本；恢复与新尝试必须有可辨认的不同动作。

以上是可评审的交互建议；尚未经用户实际试用，不锁定视觉、框架或生产接口。原型按本轮授权保留为独立本地文件，未提交、建发布分支或并入生产界面。
