## 1. 路线与现有资产

目标是个人 Windows/WSL Agent 工作台，默认与 Lead 协作，四类角色均可用 Codex/Claude；netcap 提供平台功能插件。旧 Web 会话控制台是可复用资产。OpenCode、天气、旧通知兼容与保活保留既有范围，不自动成为新工作台全部能力的前置。

| 责任 | 建议归属 | 现有资产及需要补齐的内容 |
|---|---|---|
| 原生协议、身份、审批、输入归属、操作核对 | 平台公共执行能力 | 复用 `internal/runtime`、`internal/app` 的会话/操作和 bridge；补原生拓扑、接续与完整输入权交接 |
| 目标、任务、Attempt、角色、Gate、工作区占用 | 平台协作能力 | 沿用恢复和事务经验；不能把旧原生 Goal 或对话 role 直接当作新领域对象 |
| 执行配置、能力定义与有效快照 | 平台配置能力 + CLI 适配 | 复用实例/路由/指纹；新增逐次绑定、继承解释、版本和漂移处理 |
| Skill/MCP/CLI 插件的发现与加载 | 对应原生 CLI | 平台表达选择并核对生效，不重造其模型循环、权限或全部内部工具 |
| 探测、保活、显式会话托管策略 | netcap 平台功能插件 | 通过公共会话能力申请动作；受相同暂停、容量与输入权约束 |
| Windows/WSL 接入、桌面生命周期与插件入口 | 待选底座 | 现有 React 控制台只证明 Web Alpha；需验证 Windows 端真实路径和进程归属 |

Runtime 目前已经有真实的多 CLI 差异，优先保留这个接口接缝。抽取插件时将策略与会话机制分开；不为插件再复制数据库、审批循环或目标调度器，也不要求重写全部 Go 代码。

逐项源码、首片范围和保留能力见 [netcap 功能归属清单](netcap-feature-ownership.md)。清单已补齐；插件实现及候选接口验证仍归 W04。Windows/WSL 最小控制链路须参与 W04 底座比较，安装、升级和休眠等完整验收归 W07。

## 2. 本轮验证已经缩小的风险

详细范围、命令和限制见 [关键能力实验](execution-capability-experiments.md)。以下是实验结论，尚未接入产品界面或生产适配器。

- 四份独立运行环境中的 Codex A/B、Claude A/B 同时在途，所选本地端点、测试凭据、原会话和三轮历史分别正确。
- Codex 的线程配置可以选择测试 Skill、MCP 与本地安装的 CLI 插件，排除项未出现在相应原生能力清单，后续线程仍能使用默认能力。
- Claude 的 settings、`skillOverrides`、严格 MCP 配置与会话级插件目录可以控制测试资产；已结束会话恢复后仍保留原 ID，并采用新的选择。
- Codex 预先共享后台支持第二客户端读取原在途轮次、随后继续同一会话；这不能替代独立前台 TUI 的验收。
- Claude 当前版本提供独立后台 supervisor 和 `attach`。后台会话应成为新的接入候选，不能继续把“当前 SDK Adapter 不支持”解释成“原生 CLI 没有能力”。具体认证路径与实验结果单列。

未证明：任意独立前台 CLI 的实时交接、跨窗口的输入仲裁、完整原生子 Agent 约束、机器级/账号能力全部隔离、资产调用及复杂插件 hooks、Windows 桌面端到端使用。P02/P11/P12/P15 不因本轮实验被标为产品验收通过。

## 3. 新主线的纵向切片

W01–W07 是内部开发阶段，全部首版要求仍以产品 P01–P16 和 R01–R26/R02b 为准。各片完成需实现、对应验证和证据一起存在；配置表或演示目录不算业务贯通。

| 阶段 | 用户可见结果 | 前置 | 完成依据 |
|---|---|---|---|
| W01 接续与运行身份 | 知道会话来自哪个环境、配置与原生执行器，能走经验证的接续入口 | 本轮实验 | 六入口逐项记录；独立前台、原生后台、平台创建样本分别验；活跃轮次/工具/草稿/输入权交接及双配置 supervisor 隔离有证据，未满足项保持可见 |
| W02 执行配置与能力绑定 | 登记两类 CLI 配置，启动时选择能力并看到实际来源 | 本轮实验；与 W01 交错推进 | A/B 各两份配置并发、同名/同 ID 隔离、重启回原身份；共享/专属 Skill、MCP、CLI 插件正反例，快照/改配/漂移/权限冲突成立 |
| W03 核心交互原型 | 能走通配置接入、交目标、打回修复、人工接手、恢复差异 | 产品 V0.3；不等待全部协议通过 | 原型使用标明的模拟数据；正常与失败路径可操作，用户不用理解底层字段才能完成日常动作；记录界面需调整的点 |
| W04 底座与真实插件 | 在候选底座内使用一个 netcap 功能 | W01/W02 的能力结论、W03 | 同任务比较 AionUi/Core 与 AO；Windows/WSL、接续、原生/平台插件、恢复均有适配成本；先只读状态，再显式托管一个测试会话；禁用/重启不双重调度、不丢成果 |
| W05 单目标验证闭环 | 一项工作从目标到当前产物验证，失败可恢复 | W04，所需 W01/W02 能力通过 | Goal/Task/Attempt 与 Session 分离；一次修改、一次独立 Gate、一次故障核对和人工接手；重复请求不产生第二次写入，旧证据不批准新产物 |
| W06 Lead 协作闭环 | Lead 组织探索、实现、独立审查并处理打回 | W05 | 八种角色/CLI 组合有实际证据；真实目标按发现分工；工作区冲突受控；打回→修复→再验证→集成；压缩/交接仍保留目标、配置和约束 |
| W07 桌面日常交付 | 从 Windows 开始任务、关闭窗口、恢复并检查结果 | W01–W06 的所需验收通过 | P01–P16 全部对照；WSL 发行版/用户/目录、重启/休眠、通知去重、资源规模、安装/升级与迁移演练；未解决硬要求不得宣布首版完成 |

W01 的“完成能力评估”与“六入口全部满足”分别记录。若仍有硬入口不可行，W02/W03 及可独立实验继续；最终底座承诺与首版验收不能跨过这个缺口。只有取得具体失败证据后，才向用户呈现替代路径及改变需求的影响。

W04 不要求同时部署三套平台。CAO 只作为执行实验参考。新平台必须复用已验证的会话语义，不能接受“重启回 Idle”作为恢复方案，也不能靠删掉插件需求使某个候选过关。

## 4. 旧 T00–T15 的处理

历史完成状态与原证据保留。下表改变后续路线，不追溯改写过去的验收结论。

| 旧工作包 | 新路线处理 |
|---|---|
| T00 基线 | 保留隔离开发、检查入口、原二进制保护；在 W07 使用迁移前基线 |
| T01 最小协议 | 保留固定版本 fixture；新能力以 W01/W02 增量实验补证 |
| T02 Codex 会话 | 复用会话、操作和 Web 主路径；目标工作区由 W03/W05 重排 |
| T03 审批与恢复 | 复用持久意图、丢回执核对和人工介入；W01 补真正跨端交接 |
| T04 Claude bridge | 保留 SDK 路径；W01 另验原生后台接入，不能混用两种控制端点 |
| T05 OpenCode | 保留已有兼容性与测试；不增加新的首版强制后端 |
| T06 Alpha | 保留事件、观察限制和统一操作语义；不当作 Lead 协作完成 |
| T07 路由与探测 | 已有代码，待补原生/HTTP/browser 验收；本轮 TCP/Unix 已可用，旧环境阻塞不再成立。按 W02 的路由绑定、W04 的插件探测分别复用 |
| T08 保活 | 作为插件能力后续验证；不再阻挡 Goal/Task 主线。保留既有要求 |
| T09 单 Task | 调整为 W05 的目标/尝试/证据闭环；解除对保活的强制依赖 |
| T10 Goal 队列 | 顺序派发经验用于 W05；Lead 的动态计划归 W06，平台 Goal 不绑定某 CLI 原生 Goal |
| T11 工作区并发 | 纳入 W06；与输入权、产物版本和集成 Gate 一起验收 |
| T12 路由候选与容量 | 配置/准入归 W02/W06；Lead 仅在明确候选范围选择，重连不隐式换供应商 |
| T13 通知 | 平台提供统一通知归属，插件贡献事件；兼容样例保留，真实外发仍按用户授权 |
| T14 UI/打包 | 调整为 W03/W07，Windows/WSL 桌面成为新首版核心验收 |
| T15 迁移 | 最后执行 W07 演练；旧状态、历史和用户改动不作为临时缓存清理 |

不删除旧工作包。只有明确继续旧 v1 范围时才使用旧 `IMPLEMENT.md` 的 T00–T15 顺序；“继续新产品”默认读取本计划与最新进度。

## 7. 暂定默认与必要决定

- 原型及合成实验先用 Profile 固定 Backend；Lead 候选选择保留为显式模式。该暂定值不授权切换用户的运行会话。
- netcap 首片采用“状态展示 → 单测试会话显式托管 → 人工接手/重启/禁用”的顺序；更大范围的探测、保活和旧迁移仍单独验证。
- 原型可以使用产品中的 CSV 示例；正式 W06 必须选择一个真实项目任务并写明完成条件，不能把预写脚本冒充 Lead 自主组织。
- 真实模型协作前确认并发、时间、费用/用量约束及未知指标的处理；本轮合成供应商不确定这些预算。
- 暂不锁桌面框架、协议和数据库重构方案；关键接入与插件风险会实质影响这些选择。
