# T09 · 实现单文件 Task 的完整执行与验收

## 必须先读

从项目根目录读取 `goals/EXECUTION.md` 和 `goals/PROGRESS.md`，核对前置证据后执行本工作包。所有引用路径相对项目根目录，与本文件是否被复制成快照无关。
按需阅读 `MULTI_AGENT_DESIGN.md` 第 4、7.1、7.3–7.4、8、9.2、11.2 节 M4。

## 目标与范围

实现一个文件、一项 Task、一个指定 Route 的完整路径：登记快照、认领、专属 Session、执行、验收、结果展示。顺序清单与多轮 runner 在 T10 扩展。

## 实施步骤

1. 登记 Goal/Task，校验文件、目录和路由；固定文档快照与 hash，源文件变更不改变在途任务。
2. 创建 Attempt 与专属 Session，绑定 route/config/权限快照。先持久 Task 认领、工作区占用和 Operation，再产生外部调用。
3. 用一个可在一轮完成的真实测试任务打通执行；沿用 Runtime 状态与 Unknown 处置，重连跟踪原 Attempt。
4. 实现登记的验收规则：命令使用参数数组与指定 cwd；产物校验绑定实际文件；人工验收停在 verifying，保留明确确认入口。以设计契约为准，不让模型自行改验收条件。
5. 保存验收输出、退出码、产物/报告引用和对应快照；运行结束、无未知操作、无阻塞交互且验收成立才将 Task 记为 succeeded。
6. 在 Web 完成添加、状态、结果、人工验收与失败原因展示；失败和等待验收不算 Goal 完成。
7. 在认领、发送、终态与验收落盘前后注入中断，检查重复执行和工作区占用。

## 完成条件

- [ ] 单文件 Task 可从 Web 登记到真实产物、验收结果与状态落盘。
- [ ] 快照稳定；每次 Attempt 路由/权限/原生身份可追踪。
- [ ] 工作区占用与认领原子持久；未发送证据或原执行结束前不错误释放。
- [ ] 命令失败、产物缺失、人工未确认和模型仅声称完成均不判成功。
- [ ] 断线恢复保留原 Attempt，关联未知执行后不重复创建任务。
- [ ] 实现/浏览器/故障测试通过，结果可供 T10 扩展。

## 收尾

按公共规则记录实际验证、未决事项和下一步。仅执行本工作包时，满足全部完成条件才完成当前原生 Goal；在 IMPLEMENT 总 Goal 内只更新本项进度并继续。
