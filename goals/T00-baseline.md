## 必须先读

从项目根目录读取 `goals/EXECUTION.md` 和 `goals/PROGRESS.md`，核对前置证据后执行本工作包。所有引用路径相对项目根目录，与本文件是否被复制成快照无关。
按需阅读 `MULTI_AGENT_DESIGN.md` 第 11.2 节 M0、第 11.5 节；另读 GO_BACKEND.md 与 Makefile。

## 目标与范围

建立能支持后续重构的源码基线、检查结果和隔离开发方式。本项不启动新架构实现，也不切换用户正在运行的服务。

## 实施步骤

1. 定位相关目录指令、现有源码、用户改动、运行入口与测试。仅以本项目为根；当前是否存在 Git 以现场为准。
2. 有 Git 时记录现有变更；无 Git 时对白名单源码、构建文件和设计建立可恢复快照及指纹。排除凭据、运行态、抓包正文、第三方二进制和缓存，保留用户原有源码修改。
3. 读取检查入口，运行现有 Go race 测试与 vet，记录实际结果。基线需要新执行结果时用适当的缓存控制，不能复制旧实施记录。
4. 在隔离目录构建测试 netcap，按 `tests/go_cli_smoke.py` 的实际参数运行旧 CLI 集成；发现兼容的 CLI/后台版本后使用，记录精确路径与版本。该脚本启动的 profile、后台和模拟供应商均独立。
5. 当前 `make integration` 会先覆盖 `bin/netcap`；本项用独立输出和直接测试入口实现等价检查，记录调用方式，不覆盖正在使用的产物。
6. 保存基线证据、恢复方法、后续测试使用的临时目录约定，以及真正阻塞下一项的条件。

## 完成条件

- [ ] 源码基线可恢复，用户已有改动保留，备份中没有敏感运行数据。
- [ ] Go/race/vet/旧 CLI 集成已实际执行并留结果；环境缺失与既有失败分别归因。
- [ ] 开发构建和测试使用独立产物/profile/状态；能说明测试没有接管用户后台。
- [ ] 基线发现未解决的问题不妨碍 T01 最小实验；会阻止后续执行的问题仍记 blocked。

本工作包完成代表基线与隔离已建立；既有检查失败仍必须如实记录，不能改写为通过。

## 收尾

按公共规则记录实际验证、未决事项和下一步。仅执行本工作包时，满足全部完成条件才完成当前原生 Goal；在 IMPLEMENT 总 Goal 内只更新本项进度并继续。
