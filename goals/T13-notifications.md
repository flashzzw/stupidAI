## 必须先读

从项目根目录读取 `goals/EXECUTION.md` 和 `goals/PROGRESS.md`，核对前置证据后执行本工作包。所有引用路径相对项目根目录，与本文件是否被复制成快照无关。
按需阅读 `MULTI_AGENT_DESIGN.md` 第 10、11.2 节 M6、第 14 节 F5；涉及本地通知工具前读取其 AGENTS.md。

## 目标与范围

为新领域事件提供可实际使用的常规通知入口与配置迁移，同时保留现有桌面/企业微信行为。只在测试环境验证投递，不安装用户真实 hooks 或发送外部消息。

## 实施步骤

1. 复用 T06 的事件信封和发送方契约，核对本地 .ai-agent-notify 的枚举、配置和普通投递入口。
2. 实现 Notification Adapter 及必要的旧入口兼容扩展；保留 Turn、Task、Goal、Route 的身份，路由事件使用 route ID。
3. 为新事件添加版本化独立订阅；迁移保留旧事件/渠道开关，新订阅初始关闭。不用手动 send 绕过旧偏好。
4. 保留按渠道发送预留、成功后去重、失败释放、冻结、延迟取消与恢复不补发；旧版不认识新事件时明确不兼容。
5. 按托管/观察范围明确唯一发送方，处理 hook/SDK/OTEL 的原生关联；正文相同不能覆盖独立待处理业务状态。
6. 使用 fake sender 和测试 hook 跑常规入口，包括配置升级、旧版本拒绝、单渠道失败、用户已处理问题与重复事件。
7. 保留 Windows helper/返回原终端接口；可构建或模拟的部分完成验证，真实 Windows 点击和收信效果另列待验证。

## 完成条件

- [ ] Turn 完成仍对应旧语义，Task/Goal/Route 可独立订阅并展示。
- [ ] 配置迁移保留旧偏好，新订阅不会静默开启。
- [ ] 常规入口下去重、冻结、延迟取消、失败重试通过，而非仅测试映射函数。
- [ ] 通知失败不改变任务结果；合并故障提示不合并 Session 状态。
- [ ] 现有通知工具的适用测试与兼容检查通过，真实安装/外发保持独立待办。
- [ ] 实现、配置说明和版本不兼容提示完整。
