1. 读取当前任务文件、`goals/PROGRESS.md`。新工作台任务按 [新实施计划](../docs/implementation-plan.md) 定位；只有明确执行旧 Txx 范围时才按 [历史规划](../MULTI_AGENT_DESIGN.md) 的相关章节。涉及的目录有 AGENTS.md、CONTEXT.md 或 ADR 时按实际范围读取。
2. 核对前置的代码、验证记录及当前环境。进度中的 `done` 必须有证据；新路线的依赖见新实施计划，历史 Txx 依赖见 [README](README.md) 与旧设计第 11.4 节。不一致时按当前用户要求和已修订设计核对，不混用两条路线。
3. 已实现内容先验证并复用。接续未完成工作，保留用户改动；对本任务引入的失败修复到相关检查通过，不把编码任务改写成再次输出方案。
4. 设计文档是行为契约，任务文档是执行切片。可逆实现细节自主决定；公共契约确需变更时给出具体影响，等待必要决定期间继续独立可做的工作。先查已确定规则，避免重复询问。
5. 当前任务即使被复制到快照目录，也从上述工作区根目录解析 `goals/...`、源码与设计引用。开始时记录当前任务、公共规则和设计的指纹；接续中契约变化需要核对，不能静默扩大范围。

## 实现与验证

- 沿最小纵向路径推进，每片贯穿必要的状态、执行和 UI；Runtime Adapter 隐藏三类协议差异。Application 接口是行为测试入口，协议细节在 Adapter 契约测试中验证。
- 修复故障先观察原症状，再修复并重跑。假 Runtime 验证竞争/状态，真实 CLI + 本地模拟供应商验证接入，浏览器验证实际交互；任何一层都不能冒充另一层。
- 使用项目实际存在的检查入口；新增 bridge/Web 后同步其固定版本依赖、typecheck/build/test 命令。遇到协议或第三方 API 使用对应文档 skill 查目标版本。
- 实施界面时使用适用的前端设计/浏览器 skill；React 代码遵守相关最佳实践。只读取当前步骤需要的技能资料，不启动默认委派流程。
- 相关检查通过后结束该片验证；新修改、失败或未覆盖风险才扩大测试。记录实际命令、结果、缓存命中和未执行项，不继承历史“通过”。

## 隔离与兼容

- 新入口使用独立配置、状态目录和构建产物，保留旧 `run` 的公共行为及用户正在使用的二进制。当前无 Git 时维护源码快照/指纹；提交、推送和发布沿用已有明确授权。
- 测试实例显式绑定独立 profile、后台地址和测试会话 ID。正在实施本项目的 Codex Goal 与被测 Goal 是不同对象；被测控制器只能操作测试实例，不扫描/接管当前实施会话。
- 仅清理捕获了归属的自有进程和临时资源。原生后台是否仍在工作要核对，Unknown 保留占用；当前 Goal 退出不等于测试子任务已经结束。
- 凭据沿用安全引用，日志脱敏。先使用 fake sender、本地模拟供应商、测试 hooks 和隔离迁移库。新增真实供应商调用、真实配置/共享后台切换、外部通知发送仅在已有明确授权范围内进行。
- 涉及本地 `.ai-agent-notify` 时先读其目录指令；开发兼容扩展可准备独立副本/测试入口，真实安装与迁移留到授权的切换步骤。
- 默认单代理实现。运行受控的测试 CLI 子进程是协议验证，不是把实施任务委派给其他 agent。

## 进度、阻塞与完成

1. 在 `goals/PROGRESS.md` 更新当前工作包状态、证据引用、决定和下一步；详细阶段证据按需存入 `goals/evidence/Txx.md`。只有实际执行后才创建证据记录，原始日志放在隔离目录，索引留可复现命令。
2. 工作包状态为 `pending / in_progress / blocked / done`，只描述工程进度，不是原生 Goal 状态。遇到真实阻塞记录已尝试方法、缺失条件和可恢复入口；完整实施模式继续处理技术前置已满足的独立工作，分项模式保留当前范围。
3. 完成条件里的“且”都要满足。核心验收未执行、失败未修复或证据不足时不记 done；已有不相关失败单列。真实上线操作不属于本地实现完成门槛，必须在交付中明确尚未验证。
4. 一个工作包仅在本地结果、验收和收尾均完成后记 done。单独执行它时可完成当前原生 Goal；在 IMPLEMENT 总 Goal 内只更新工作包进度，继续下一项。
5. 原生 Goal 状态更新遵守当前工具规则；工程进度记 blocked 不等于立即调用同名原生状态工具。用户未要求暂停时不自行暂停目标；预算或用量限制不通过替换目标/另建会话绕过。
6. 用户未指定 token budget 时不设默认值。完成一个切片不代表整个总 Goal 完成；总 Goal 的结束条件由 IMPLEMENT.md 定义。
7. 交付说明已实现结果、实际验证和剩余限制。清除本次临时调试内容，保留可重复的 fixture 和必要证据，核对最终差异。

每个证据记录至少回答：改了什么；验收条目分别如何验证；哪条命令通过/失败/未执行；使用什么版本和隔离实例；未解决问题是什么。证据和实现一起更新，避免另建重复状态表。
