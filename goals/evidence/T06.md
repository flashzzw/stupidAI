## 观察入口、事件与通知契约

- 新增 `internal/events`、Application 观察入口及 `domain_events/observation_receipts` 持久表，schema 2 兼容读取旧 schema 0/1。来源由配置固定实例、项目、格式、专用 env token 与通知处理方；事件只读，不能赋予 Runtime 控制权或可信路由。
- 原生轮次/请求与 Operation 关联；请求关联包含 connection ID，跨重连同编号不合并。来源缺少可靠引用时保留独立事件，不按文案去重。Runtime 对托管范围保持权威，合并保留来源集合；Task/Goal/Route 各有独立主体与事件类型。
- 观察事件可投影只读状态和 Pending；观察会话跳过 Runtime 轮询。迟到事件进入账本但不复活旧请求或已取消通知；控制台重启不伪造观察来源的连接变化。
- `internal/notify` 固定 version 2，接受旧 version 1 的有效配置并保留开关、事件、渠道及 behavior；新 Task/Goal/Route 订阅缺省关闭。旧接收端明确拒绝不支持的新类型。`Candidates` 经来源、唯一处理方、订阅、渠道及 event ID 筛选，由 fake receiver 验证，尚无外部发送器。
- 托管通知归属来自实例，观察归属来自 observer；缺省 legacy。真实配置/hook 保留与隔离证据沿用 T03–T05 的已执行矩阵；T06 新增 Application → DomainEvents → Candidates → fake receiver 的整合测试，覆盖 Runtime/hook 重叠、相同文案不同会话、两个 owner、渠道独立和迟到取消。

## 失败与修复记录

1. fake sender 捕获到缺原生轮次 ID 的旧完成事件仍可通知；新增活动时间检查后，Runtime/hook 关联和无引用迟到事件均保持取消。回归先失败后通过。
2. 浏览器发现观察请求重启后错误显示“原连接已变化”；HTTP 回归先失败，再让 observed 跳过托管连接失效处理后通过。仍不提供观察回复能力。
3. Claude 丢创建回执测试仍使用 45 秒旧期限，早于 T05 新增的 120 秒初始化期限。持久调用记录证明仅一次 create、原回执已被测试代理丢弃；测试等待改为 150 秒后原创建、发送和截断日志全部通过，没有放宽生产恢复判定。
4. 浏览器测试修正了 select 的 label 文本匹配、带关闭按钮的 alert 文本匹配、Claude 能力说明后缀、原生 option.disabled 检查，以及完整证据恢复后自动核对抢先移除按钮的竞态；产品数据和控制逻辑未为这些测试故障改变。浏览器工具不提供文件系统模块，恢复测试改由外部 harness 分阶段注入故障。
