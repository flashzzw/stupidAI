日期：2026-09-29。状态：done。T04 的本地验收完成；M2 还需 T05/T06。

## 交付

- `bridges/claude/` 固定官方 SDK 0.3.280、TypeScript 5.9.3、Node 类型 24.10.1；实际 CLI 2.1.280 / Node 24.13.0。NDJSON v1 握手；bridge 负责 query、输入 UUID、原生事件/回调与持久 journal，Go 负责命令、准入和结果。
- SDK 显式指定 executable/cwd/claude_code preset/settingSources/env/model/permission/persistSession。每 query 构造 route env，不改 process.env。普通会话加载 user/project/local；probe 使用独立 profile/cwd、sources=[]、最小工具和关闭的工作 hooks。
- `internal/runtime/claude*.go` 实现 Runtime 和 bridge 通道；`NewAdapters` 分派 Codex/Claude。配置新增 bridge/node_executable，Claude profile 对应 CLAUDE_CONFIG_DIR；凭据只读 env 引用，经 stdin 传递，不进入 metadata。
- 输入 UUID 与 Go Operation 关联，官方 getSessionMessages 读取原生历史，SDK 结果/后台事件先 fsync journal 再核对。证据不足不重发；不能热接管任意独立 CLI。外部用户历史令会话进入 Unknown/人工接管。
- 原生 canUseTool 支持批准/拒绝、AskUserQuestion 和连接有效性校验；网页显示具体命令/路径及可展开工具参数。中断验证自有输入并停止该输入产生的 SDK 后台 task，收到完整终态与后台集合清空才释放。
- Go 为 bridge 传递实例 flock，旧 bridge EOF 清理期间不允许第二个控制器。确认所有已知会话空闲、30 秒无新操作后回收 CLI/bridge；空闲只读视图最多缓存 30 秒，发送和未决操作核对始终查询新证据。Unknown/审批/后台占用不会被回收策略当作空闲。
- 正式入口、配置示例及使用说明已同步：`make claude-deps claude-build claude-contracts claude-integration claude-recovery claude-idle`、`console.example.json`、[bridge 说明](../../bridges/claude/README.md)、[工作台说明](../../CONSOLE.md)。

## 发现、修复与限制

- SDK 的模型轮次结束不等于后台 Bash 结束。真实实验先复现 stop 拒绝，再按输入归属接入 stopTask；完整集合终止后才释放。bridge 消失而任务未核对时返回 Unknown，回归先失败再通过。
- 当前 SDK 的自动中断提示没有 isSynthetic；不能靠正文识别人类。依据自有 SDK 事件 UUID、原输入 UUID 和 isReplay 关联原生生成消息。相同正文但没有对应自有事件的外部用户输入仍保持 Unknown。测试先失败后通过，真实 HTTP/浏览器已复验。
- CLI session ID 不一定出现在进程 argv；故障 fixture 通过创建记录、隔离 profile 环境和 cwd 验证进程归属后才发信号，不只依据旧 PID。
- 初步单实例 RSS：Go 13248 KiB、bridge 91776 KiB、CLI 223568 KiB；回收后 Go 17088 KiB，bridge/CLI 已退出。完整多实例资源/打包目标仍属 T14。
- bridge dist 可重建、未纳入源码；本地交付依赖 Node 与锁定 SDK。任意独立 CLI 不可热接管，旧回调无法凭持久 ID 恢复；转人工仍保留未知账本。
- 未执行真实供应商保活、外部通知、用户状态切换。T07/T13/T15 的专门验收仍需继续。
