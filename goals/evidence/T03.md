日期：2026-09-29（Asia/Shanghai）。状态：done。T02/T03 的本地 M1 验收通过；首期 v1 仍需 T04–T15。

## 已实现

- `internal/codex/proxy.go` 提供连接身份、有效请求集合和回复原始 JSON-RPC request ID 的 `Respond`；消费 `serverRequest/resolved`，原子认领防止重复回复。
- Runtime 支持原生审批、阻塞问题和异步问题；回复前重新核对请求。异步 `agentMessage.questions` 使用关联的 `turn/steer` 或 `turn/start` 输入，不伪造 RPC response。完整旧式历史用于补齐当前内存投影遗漏的异步问题。
- Application 持久化 PendingAction 与 prepared/dispatching/终态；暂停 generation 撤销未发送操作，发送回执不等于执行完成。重启 prepared 可确认 not_sent，其他未决操作保持核对；旧连接请求标记 unverified。
- 创建按 threadSource/cwd/provider/model 找回原生身份；发送按 operation ID 与正文找回原轮次。错误关联不释放占用，查询不完整保持 Unknown，转人工仍保留暂停和只读核对。
- 执行范围检查包含根会话及子会话的队列、原生 Goal 和后台终端。子会话 idle 间隙仍有 queue/Goal 的缺口已先复现失败，再修复并通过测试。
- 中断前检查轮次自有输入；异步问题回答也计为自有输入。发现人工消息则暂停自动化、转人工。
- Web 有原生审批选项、回答表单、停止轮次、关联原执行、Unknown 证据、转人工和可复制原终端命令。丢 HTTP 回执保留 command ID/hash；正文和答案不写入浏览器存储。

## 发现、修复与边界

1. 子会话 idle 时仍可能有队列或 active native Goal：回归先失败，再将同一执行范围检查用于子会话，测试通过。
2. Codex 0.158.0 的 `turn/steer` 回执先于人工输入进入历史；等待中的输入暂时不出现在 history 或 queue。中断保护基于原生可见证据，不能声称拥有原生端未提供的跨客户端原子锁。混入后的真实拒绝路径已通过；接管时仍应先在网页暂停并转人工。
3. 未落盘新线程可能在后续连接失效后消失。候选已经不可读取时必须保留 Unknown；不能重建一个同名线程伪装恢复。浏览器验证了此失败出口和仍可读取候选的成功出口。
4. 浏览器测试曾在故障混合实例中错过 1.2s 的短流式中间态；独立 T02 实例重跑通过。完整负载/资源测量仍属 T14，不据此声称已通过高负载流式延迟验收。
5. 浏览器重启实验最初在服务重新监听前导航导致 connection refused；等待实际就绪后恢复验证通过。终端命令未换行问题已修复，实际元素无横向溢出。

没有验证真实供应商效果、外部通知、用户共享后台切换或真实状态迁移。总 Goal 保持 active；后续从 T04 继续。
