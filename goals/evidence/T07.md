## 原生 UTC 工具证据实验

`tests/route_probe_evidence.py` 已用三类真实 CLI 在各自本地供应商上完成实际日期工具调用和精确最终响应。首次结果日志 `.dev/logs/T07-native-date.log`；固定包装命令输出退出码标记后再次通过，日志 `.dev/logs/T07-native-date-marker.log`，原始证据 `/tmp/netcap-console-q5pife31/*date*`。每类 2 次模型请求（工具调用与最终回答），没有实际外部供应商。

发现：OpenCode tool part 的 `state.metadata.exit` 为真实退出码；Claude 0.3.280 SDK BashOutput 与实际 `tool_use_result` 没有独立 exit-code 字段，不能据 stdout 猜测；Codex 的 `functions.exec` 嵌套调用不出现在 thread/read 的工具项中，但原生 rollout 的 custom_tool_call/output 保留相同 call_id/turn_id 和 exec_command JSON 结果。第二次实验使用固定包装命令调用 `/usr/bin/date -u +%FT%TZ`，将其 `$?` 和 UTC 值打印为 `__NETCAP_UTC__<exit> <UTC>`，然后以该退出码退出；三类返回给模型的原生工具输出均含 0 与实际 UTC。后续自动探测需验证原生命令与调用身份、包装输出和最终答案，不能只搜索最终回复中的时间。

这些是证据实验，尚未接入自动探测、隔离策略生成或调度准入。原型命令与模型响应仅在自有测试项目执行，审批由 fixture 明确核对后回答。官方 Claude Bash 输出字段与本地固定 SDK 类型一致：`https://code.claude.com/docs/en/agent-sdk/typescript`。已获取 Codex 官方 config-schema.json（`.dev/logs/T07-codex-config-schema.json`）及本地 0.157.1 App Server JSON schema（`.dev/logs/T07-codex-schema`）；ConfigReadParams 仅有 cwd/includeLayers，没有 threadId，不能当作每线程有效配置查询。

## 第四片：Codex 凭据绑定实现与离线回归

2026-09-29 接续。已复核 T07/EXECUTION/设计文件与 `.dev/logs/T07-contracts.json` 指纹相同；前一轮有代码、测试和证据变更，归类 progress。本片仍未启用生产 probe/route_evidence 能力。

### 已实现

- `codex_route.go` 将创建和 unloaded-thread 恢复的覆盖收敛为 endpoint、env_key、requires_openai_auth=false；config/read 仅用于核对分层 provider 配置中的冲突来源。额外 bearer token、command auth/AWS/gateway auth、已知认证 header、附加 query 参数或不可安全表达的 provider 名称均在原生写入前拒绝。普通元数据 header 保留。发送前另外核对原生 thread ID、cwd、model/provider；turn/start 重申 model/cwd。
- `codex_peer.go` 从显式本地 socket 的 SO_PEERCRED 捕获同用户 daemon PID，与进程 birth、socket inode 一起绑定到 proxy；运行映像通过 `/proc/<pid>/exe --version` 核对 0.158.0。proxy 建立前后检查身份一致，随后关闭临时 peer 检查连接；socket/进程变化后废弃原连接并重新核对，不扫进程、不重启共享后台。
- 模型写入前，仅读该已定位 daemon 的 `/proc/<pid>/environ`，有界核对绝对 CODEX_HOME/profile 和所选 env 值。拒绝缺失、重复、不完整、profile 不同或凭据不一致的环境；不把原始环境/认证值写入错误或日志。核对控制台值不等于改变后台值，轮换只重启控制台时仍拒绝发送。
- `Scope.CredentialStamp` 保存 env 引用和值的单向指纹，路由配置 fingerprint 也包含该指纹。即使未增加 revision，env 值变化也不会共享旧健康或沿用旧会话；创建/发送/回复在 Adapter 边界核对。旧 env 会话缺少快照时不臆造旧值，保留历史和定位记录，拒绝新写入。Codex 自有探测后台重建前也核对原凭据快照。
- 原生创建明确返回 NotSent 且没有 native ID 时，将本地未创建会话收尾为 closed；不再把这个确定未创建的记录永久算作 Unknown 占用。原生结果 uncertain 的占用规则保持。
