## 目标与范围

把 T02 变为可验收的 M1：真实工具审批可回复，中止/接管可核对，Unknown 有可操作的人工出口。

## 实施步骤

1. 扩展 Codex Client 的服务端回复通道；回复原生 request ID，区分普通 Call、新请求、阻塞回复与异步问题消息。
2. 实现 PendingAction 的持久记录、批准/拒绝、原端抢先处理、清除和过期。连接变化后先验证请求有效性，再提供回复操作。
3. 按设计给 Reconcile 返回 NotSent/Running/Finished/Unknown 及证据；查询不完整不能判未发送。
4. Web 增加证据详情、重新核对、验证后关联原生执行、转人工。转人工保留只读核对及未知占用，普通 retry/resume/probe 不直接清空 Unknown。
5. 实现暂停与接管 generation：先持久暂停意图，仅撤销自有待发送项；中断前确认轮次归属，人类已混入的工作按设计让路。
6. 通过真实 CLI + 模拟供应商触发本地工具审批；通过可控故障 fixture 覆盖发送前、中途断线、丢回执、部分历史、进程退出和迟到事件。
7. 核对重启后的执行/子任务归属，浏览器完成 M1 的实际流程验收。

## 完成条件

- [ ] 真实工具审批的批准和拒绝均生效；双击、过期、原端已处理的请求不重复回答。
- [ ] 创建或发送回执丢失后核对原操作，不产生第二次执行。
- [ ] 永久证据不足可以转人工；占用与任务结果保持真实，不因接管自动判成功或取消。
- [ ] 只有证据确认未发送或执行及相关子任务结束，才释放对应占用。
- [ ] 暂停及时持久化，重启和迟到回调不能重新启动已暂停动作。
- [ ] T02/T03 的 Web、协议及适用 race/构建检查通过，M1 证据完整。

不通过强制 full-access 规避审批路径；测试只操作隔离实例，不能修改当前实施 Goal。
