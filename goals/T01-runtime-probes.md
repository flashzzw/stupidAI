# T01 · 验证三类 agent 的最小协议与配置策略

工作目录：`/home/zzw/codex-netcap`。里程碑：M0。
技术前置：T00。

## 必须先读

从项目根目录读取 `goals/EXECUTION.md` 和 `goals/PROGRESS.md`，核对前置证据后执行本工作包。所有引用路径相对项目根目录，与本文件是否被复制成快照无关。
按需阅读 `MULTI_AGENT_DESIGN.md` 第 4.3、6、11.2 节 M0；参考仓库通过设计第 13 节固定来源定位。

## 目标与范围

为 Codex、Claude Code、OpenCode 各提供可重复的最小协议实验，证明后续统一 Runtime 的接入前提。M0 不承担完整故障矩阵或 Goal 工作流。

## 实施步骤

1. 用官方文档、本机 help/schema 与参考实现核对协议，记录实际 CLI/SDK/后台版本。仅安装本项目需要的固定版本开发依赖，保留用户现有 CLI 安装。
2. 每类使用隔离 cwd、profile、自有后台和模拟供应商；建立可观察请求去向的两个本地端点，使用测试凭据。
3. 创建会话、完成两轮交互、记录稳定原生 ID；上一轮结束后重建控制客户端，读取历史并继续同一会话。
4. 分别选择两个端点验证 route 确实生效；记录有效模型、配置及认证来源，避免只检查发送参数。
5. 为普通工作会话和探测会话形成第 4.3 节的配置策略记录。Claude 记录 executable、preset、settingSources、env 及配置入口；OpenCode 记录目录配置作用范围。
6. 将可重复脚本和最小脱敏 fixture 保存在项目测试区域；只保留必要依赖和源码，不把整个参考仓库复制进项目。
7. 输出 `supported / unsupported / unverified` 能力记录。中途断线、审批、进程归属由 T03–T06 补验，native Goal 由 T10 补验。

## 完成条件

- [ ] 三类 agent 均通过两轮交互、已结束会话恢复与指定端点证据检查。
- [ ] 脚本可复现，版本固定；精确参数和示例来自当前协议而非猜测。
- [ ] 配置策略与未验能力有清单，并明确后续工作包归属。
- [ ] 真实 CLI 与模拟供应商之间的证据可区分；未拿假 Runtime 冒充真实接入。
- [ ] 未验证的中途恢复/审批不被标为已支持。

某类核心接入失败时保留其 blocked 与诊断。替换为纯 mock 或删除该 agent 不满足本 Goal；可继续另外两类独立实验。

## 收尾

按公共规则记录实际验证、未决事项和下一步。仅执行本工作包时，满足全部完成条件才完成当前原生 Goal；在 IMPLEMENT 总 Goal 内只更新本项进度并继续。
