## 目标与范围

在已可靠的串行清单上增加 depends_on 与受控并发：独立工作区可并行，同一可写工作区互斥。

## 实施步骤

1. 增加依赖字段与导入校验：重复 ID、缺失依赖、循环依赖拒绝登记；运行中变更重新校验且不篡改当前 Attempt。
2. 将顺序语义与显式依赖/并行策略区分；默认串行，失败依赖不解锁下游，独立项是否继续服从 Goal 策略。
3. 复用已有占用模型，按真实路径和目录重叠判断工作区冲突；共享 Git 管理操作/公共产物资源额外串行化。
4. 用单写者事务认领 Task、Attempt、Operation 和容量，确保同 Task/Session 不重复执行。queued 等待不占模型执行槽，原生 Goal 自主运行持续占用。
5. 开放全局/route 上限内的独立 Task 并发，UI 展示依赖和资源等待原因，保留原串行路径。
6. 使用至少两个 agent、两个隔离工作区、一个重叠目录及有依赖/无依赖任务验证；注入认领后崩溃、暂停抢先、迟到终态。
7. 外部人工工作无法被本系统锁强制控制；观察到冲突按既定接管策略让路，明确可观察范围。
