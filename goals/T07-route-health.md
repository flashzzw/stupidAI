从项目根目录读取 `goals/EXECUTION.md` 和 `goals/PROGRESS.md`，核对前置证据后执行本工作包。所有引用路径相对项目根目录，与本文件是否被复制成快照无关。
按需阅读 `MULTI_AGENT_DESIGN.md` 第 4.2–4.3、5.1–5.3、8、11.2 节 M3。

## 目标与范围

让用户明确选择实例/账号配置/端点/模型，并按这条 Route 的真实模型请求记录健康。只实现手动与按需探测，周期保活由 T08 实现。

## 实施步骤

1. 完成多实例/Route 配置和页面，版本化关键配置，发送前核对漂移；凭据保存引用，展示有效路由来源。
2. 健康键包含实例、供应商、端点、模型及凭据/配置 revision；同名模型不同端点不共享成功证据。
3. 通过对应 agent 执行 UTC 日期探测，核对真实命令、退出码、输出与最终响应；纯文本探测另标仅生成能力。
4. 复用 T04–T06 验证的探测隔离策略；不以本地 health、进程启动或请求接受代替探测成功。
5. 实现 TTL、同 route 的实际成功刷新、单 route 探测合并、错误分类与退避。内部 retry 期间外层保持在途，控制断线先对账。
6. 实现准入所需的全局/route/session 容量与人工优先，手动探测也经过准入。
7. 使用两条可辨识模拟路由覆盖认证错误、限流、服务错误、工具失败、配置漂移和 Unknown，页面展示原因与下次允许时间。

## 完成条件

- [ ] 三类 agent 都能在所选路由上完成真实工具探测，路由去向有证据。
- [ ] 健康状态按配置身份隔离；TTL 内不重复无必要探测，失败不会被旧成功掩盖。
- [ ] 工具故障/单会话问题不误标整个供应商；认证/限额不被无界重试掩盖。
- [ ] 无重叠外层重试；未知控制结果先核对；手动探测不绕过人工占用。
- [ ] 只读 doctor 不产生模型请求，页面与相关测试通过。

真实供应商的空闲阈值尚未测量时保留未知，不用模拟路由结果代替真实效果。

## 收尾

按公共规则记录实际验证、未决事项和下一步。仅执行本工作包时，满足全部完成条件才完成当前原生 Goal；在 IMPLEMENT 总 Goal 内只更新本项进度并继续。
