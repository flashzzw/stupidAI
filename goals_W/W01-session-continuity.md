## W01.02 · 接续来源与分项能力入口

**前置**：W01.01；已有版本与连接方式描述。

**实施与产出**：将环境、CLI 配置、原生执行器、状态命名空间和接入前提贯通接续列表/详情。分别显示新建、历史、恢复、实时观察、实时操作；接入既有会话先预览证据和控制限制。

**验收**：只读来源不能获得发送权；日志观察不变成实时操作；新建、预共享后台和独立前台在 UI 与 API 中可区分，不静默 fork 或换 Backend。

## W01.03 · Codex 独立前台与原线程接续

**前置**：W01.01；既有 B01/B02、C02 样本。

**实施与产出**：保留预共享后台正例，针对 --no-daemon 独立前台验证可用控制入口。把能证明的路径接到生产接续入口，记录启动准备、执行器是否变化和返回原终端方式；失败则形成具体替代路径及影响。

## W01.05 · 在途工具故障与恢复边界

**前置**：W01.01；已有可运行的 Codex 共享后台与 Claude 后台 fixture，独立于严格前台入口继续。

**实施与产出**：针对 attach、控制进程、supervisor、worker 分层注入故障。优先处理已复现的 Claude worker 死亡后原工具仍活、输出未回到模型问题；按原生证据判断继续观察、待核对或显式交接。

**验收**：不能用 roster idle 清除占用；工具执行次数、结果归属、审批有效性和重试责任有证据。若输出不可恢复，保留未满足状态和可恢复出口，不自动重做外部副作用。

<a id="w01-06"></a>

## W01.06 · 输入争用与六入口联合验收

**前置**：W01.02–W01.05 的所需实现及证据就绪。

**实施与产出**：覆盖终端输入、平台输入、暂停、迟到回执、连接切换、未提交草稿、审批/工具在途的交接顺序；分别执行六入口并把限制接到实际按钮和停止原因。

**验收**：每个样本记录原 ID、执行器、消息/工具计数、控制归属、草稿处理和最终产物；失联仍保留占用，人工接手阻止后续自动输入。P02/P06/P07 的范围和剩余项逐条可查。
