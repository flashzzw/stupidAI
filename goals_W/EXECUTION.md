# W 系列执行与验证规则

工作区：`/home/zzw/codex-netcap`。适用于本目录任务；当前用户要求、项目指令和实际工具权限优先。规划文件不授予真实环境切换、发送外部消息或发布权限。

## 开始与选择

1. 读 [PROGRESS](PROGRESS.md)和当前子任务。遇到领域行为读 [CONTEXT](../CONTEXT.md)；需求、交互和架构问题分别沿任务里的指针读取上游文档，已有 ADR 按影响范围核对。
2. 查看当前改动、调用方和相关测试；保留用户改动。核对依赖的具体证据与当前环境，历史通过不等于本轮重跑通过，局部正例不提升整包状态。
3. 默认单代理逐片实施；受控 CLI fixture 用于协议验证，与委派开发任务区分。用户明确要求并行协作时再按其范围执行。
4. 本主线从当前进度继续，已完成切片在受影响时回归；不要因 Txx 文件存在转回旧路线。W 包编号不是强制串行依赖，选择顺序见 [IMPLEMENT](IMPLEMENT.md)。

## 切片与契约

- 每个子任务交付可观察行为及验证，贯通必要的状态、执行和界面；沿真实变化点复用 Runtime/Application，避免先搭全平台目录。
- 需求和 [产品设计](../docs/product-design.md)定义目标，任务文件定义可交付切片。可逆细节自主决定；涉及目标或公共契约的实质变化先完成证据和具体方案，必要决定期间继续独立工作。
- 继承/计划/实际加载/已使用分别记录；平台插件与 CLI 插件分别管理。保存摘要不等于冻结原生运行状态。
- 使用已确认的会话身份与持久操作入口；平台、插件和 CLI 原生循环各自保留唯一职责。结果未知先核对，不用新执行伪装恢复，也不把清理工作区作为停止的副作用。

## 验证与隔离

- 验证层次分开：状态/竞争通过现有接口测试；协议通过真实 CLI 与本地模拟供应商；交互通过浏览器；Windows 宿主通过真实宿主链路；角色行为通过真实任务。模拟数据不能替代后一层证据。
- 修复 bug 先观察失败，修复后重跑相关验证。按 Makefile、CI 和测试入口选择检查；相关检查通过后，仅因新修改、失败或未覆盖风险扩展测试。纯文档任务检查内容、引用、覆盖与差异。
- 使用独立 profile、项目、状态目录和开发构建 `.dev/bin/netcap`；保留旧 `bin/netcap`、用户配置和旧 `run` 行为。凭据用既有引用，日志/产物脱敏；只清理已证明归属的自有测试进程。
- 原生 CLI、SDK 或框架接口按目标版本查官方资料或适用文档 skill。复用已有调研，不扩展开源候选；W04 的证据门槛满足后才收敛桌面框架、通信和数据库取舍。
- 先完成本地模拟供应商、fake sender、临时 hooks、隔离迁移副本等可独立工作；真实供应商调用、共享后台切换、用户状态迁移、外部消息与发布按已有明确授权执行。需要额外决定时说明具体对象和影响，不重复询问已授权事项。

## 状态与证据

工程状态统一为 `pending / in_progress / blocked / done`：

| 状态 | 含义 |
|---|---|
| pending | 尚未实施；前置未满足或等待届时必要输入，在备注中说明 |
| in_progress | 已有部分实现/实验，仍有该项必需工作或验收未完成 |
| blocked | 当前工作确实无法推进，记录复现/尝试、缺失条件和恢复入口；独立任务仍可继续 |
| done | 该子任务定义的实现、实际验证及收尾均完成，且有对应证据 |

状态只在 [PROGRESS](PROGRESS.md)更新；工作包 done 还须满足其整包条件，不能只按子任务数量计算。首次整理继承已有证据，明确其日期、范围和未验证部分。旧 W 记录保存在 `goals/`，新增证据按 [约定](evidence/README.md)写入本目录。

每片收尾记录：用户可见变化、完成条件分别如何验证、命令与通过/失败/未执行、被测版本和隔离范围、产物版本/哈希、限制与下一步。更新受影响的需求/使用说明，核对最终差异；仅实际执行之后生成验收证据。

工程 blocked 与原生 Goal 状态是两个对象，后者遵循工具规则。没有明确要求时不创建原生 Goal 或默认 token budget；完整实施中的工作包切换不重置目标或预算。单个切片完成不等于整个 W 系列完成。
