# W02.09 · 共享 MCP 启动版本与原 ID 切换

日期：2026-10-10。范围：普通 Codex 的共享 stdio MCP 定义、原会话改配、加载与历史调用版本；四配置和混合能力回归。W02.09 仍为 `in_progress`，完整 W 系列保持 **9/40 done，Goal active**。

## 交付行为

共享 MCP 现可新增、启停、明确选择同名资源的新版本和恢复继承。复用原有候选、准备、持久操作、原 ID 退订/恢复、只读核对与明确恢复入口；保存和准备不提前晋升。撤去最后一个显式服务时，仍核对完整清单和已撤下服务，不能因目标为空而跳过。

格式 2 的 `MCPDefinition` 新增资源版本、资源树摘要与 `binding`。启动摘要包含稳定的会话/配置/状态归属、来源及实际展开的命令、参数、环境；原生 ID 在创建前尚不存在，不参与摘要。快照只保留身份、摘要和环境名，不保存命令参数或凭据值。禁用不读取无用凭据、不启动转发器；重新启用是明确的候选绑定。格式 1 记录维持兼容，不补造加载证明；既有资产 ID 及 200 字节版本长度范围保留。

`internal/mcpstdio` 在实际子进程启动前复核交付值，并保持 JSONL 双向通信。它把启动标识附在初始化的 `capabilities.experimental["netcap/binding"]` 和工具结果的 `_meta["netcap/binding"]`。上游若占用同一键，原值保存在 `upstream`；其他元数据、工具内容和数值精度保留。私有 CLI 入口不经过普通配置解析。

Runtime 核对原生清单中的实际标识，按每次调用结果的标识区分历史。旧版本、缺少标识或未知插件来源的调用不自动归入当前同名资产。页面展示计划、实际加载及历史版本；权限守卫仅要求当前显式选择通过，不把历史行误当未验证的当前能力。

## 原生边界与验证结果

固定版本为 Codex proxy **0.157.1**、app-server **0.158.0**、Claude Code **2.1.280**。使用 `/var/tmp` 自有目录、bwrap user/PID/net/mount 隔离、自有策略、模拟注册表缺席、本地脚本化供应商及自有 MCP。未调用真实供应商或用户后台。

直接协议探针确认：热 `thread/resume` 返回成功仍可能使用旧定义；退订后可在原 ID 上新增、替换和撤去。但同线程存在第二订阅者时，退订/resume v3 仍可能继续使用 v2，且退订状态、`thread/read` 的 idle 和 loaded 清单无法证明换版。真实 Go 转发器的 **105 项**探针保留该反例；探针通过表示边界断言通过，不表示每次切换成功。

生产验收覆盖四配置与同后台另外两条线程，共六个独立 ID。最终开发构建通过 **217 项**：

- 新增和同名 v2 应用后，实际工具返回独立版本/进程标记，启动与调用标识一致；其他资源及线程维持各自版本。
- v2 来源漂移只影响引用该版本的执行；输入在原生派发前被阻止，恢复原文件后保留原绑定。
- 第二订阅者下 v3 候选保持未知、当前快照仍为 v2；重启保留同一候选与操作，不重发输入。原生仍报告 v2 的启动标识，未实际调用 v3。
- 在自有后台重启并确认原线程未加载后，明确恢复原 ID 的 v2；失败 v3 单独归档，不进入生效历史。恢复与改配不调用模型。
- 恢复继承后共享服务撤下，原有继承 keep 与专属服务仍可调用；另一线程只撤去最后一个显式服务，原生清单仍保留 keep。

最终一轮共有 **42 次本地模型请求、21 次工具调用、21 次单次审批**。只读审计从原生历史、SQLite、HTTP、源文件字节及真实展开环境独立重算，**154 项**通过；核对 11 个执行快照与三个目标线程的 12 次原生历史 MCP 调用。未用脚本化模型证明自主方法或 Gate。

## 修复与失败记录

所有失败日志与原始材料保留。

1. 转发器透明直通的初始实现缺少加载标识；补标记后通过大于 64 KB 的 Unicode、`9007199254740993` 精度、原元数据、同 ID 服务端请求和错误响应检查。race 夹具的默认退出等待与 1 秒宽限冲突，测试子进程设置 `GORACE=atexit_sleep_ms=0`，未放宽生产超时。
2. 生命周期测试发现正常子进程退出后，关闭自有输入会被误报为传输失败；修复后正常退出、取消、EOF、不合作进程、同进程组后代和父转发器死亡的直接子进程检查通过。
3. Application/Runtime 红灯分别覆盖缺少或错配的绑定、同名旧进程、历史归属和空目标撤下。保存方案重建遗漏 MCP 目标版本导致准备认为无差异，已修复并通过持久化/丢回执/重启回归。
4. 真实 v2 切换成功后，下一条输入曾被拒绝：权限守卫把 `history` 行当当前未验证选择。原输入确认 `not_sent`，没有重发；补接口回归后修复，后续原生验收通过。
5. 最终检查发现转发器名称/版本限制比既有资产契约严格，先复现 `_`/`-` 开头名称及长度边界，再恢复兼容并重跑最终构建验收。
6. 原生夹具前两轮遗漏执行配置登记；第三轮 experimental 能力值错误使用字符串，导致初始化失败。纠正后保留原失败，未将其计为产品通过。
7. 直接探针曾遇到 rollout 尚未落盘及历史短暂 `interrupted` 采样；改为继续观察同一输入的 `turn/completed`，不重发输入。浏览器按钮名称、未等预览渲染和窄屏详情面板的假设已纠正。
8. 审计曾把 HTTP 派生 `access` 字段当作 SQLite 持久字段，并忽略原生 `serverInfo` 补齐的 null 字段；改为核对持久绑定及实际声明字段，未放宽版本/来源要求。清理首检与只读审计进程重叠，顺序复核后自有原生进程均已结束。
